# 架构

`main.tsx` 挂载 React，`App.tsx` 只编排页面区块。UI 沿用暖白背景、路线主题色、统一卡片、桌面三列 / 中屏两列 / 手机一列。

- `domain/models.ts`：严格类型。
- `data/`：纯数据，事实与玩家配置分开。
- `utils/`：纯计算、推荐派生、路径格式化、导出及存储边界。
- `components/`：小范围页面组件，不解析 Wiki、不持有数据库副本。
- `hooks/`：主题、招募进度、防剧透生命周期。
- `services/portraits.ts`：Wiki 请求、解析、会话缓存、10 秒超时与回退。

## 防剧透

普通数据不包含后期人物。成长表用无姓名 rank 占位维持 53 行。只有 dialog 第二次确认才动态 import `data/spoilers`。界面、导出共用可见数据；重新隐藏卸载后期内容，刷新状态归零。已下载模块仍可能在浏览器缓存中，因此这是防意外阅读机制，不是访问控制。

## 持久化

命名空间 `fortune-weave-planner:v1:`；主键使用稳定英文 ID + 路线 + 分类。新键缺失时读取旧中文名键，复制但不删除。新值始终优先；配额不足时保留可读旧值并显示提醒。后期清单解锁时才读取，解锁本身不持久化。

## 外部依赖与扩展

Wiki 只影响头像，请求结果（包括失败）会话缓存。组件处理单图错误，图片保留源比例。

详情页可组合角色、招募、成长、build 与 Meta；阵容 Builder 复用 availability 与推荐。职业模型预留成长修正和武器经验，未知修正为 null。未来模拟器必须先验证数据完整度，本轮不实现大型玩法模拟。
